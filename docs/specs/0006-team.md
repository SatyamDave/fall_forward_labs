# quant-core team spec (from the repo owner; runs after base Phase 0 once the vertical is chosen)

Two human founders, each with own Claude Code sessions/machines/times. Goals: (1) any Claude session from either founder, any directory, guided the same (mission, milestone, rules, procedures); (2) founders coordinated without constant meetings (ownership, visible decisions, clean handoffs); (3) every merged PR leaves the system measurably better and more proprietary (quality ratchets up, knowledge compounds in the repo); (4) IP protected (alpha encrypted at rest, scoped access, no leaks via tools, logs, third-party APIs).
Principle: **Text guides, hooks and CI enforce.** Both founders review and approve every phase.
Rules: plan in docs/plans/0006-team.md; one phase per PR; stop for approval; verify Claude Code features (memory, settings scopes, hooks, managed settings, skills, plugins) against current docs.

## Phase 1 — one brain
docs/NOW.md (≤40 lines), read at every session start, updated by knowledge loop + founders:
```
# NOW  (updated: YYYY-MM-DD)
Vertical: <chosen vertical>          Scope rule: general interfaces, one implementation
Current milestone: <e.g. M2 — demo paper trading for strategy X with full risk engine>
Definition of done: <3–5 checkable bullets>
This week's priorities (ranked): 1. … 2. … 3. …
Not now (do not work on): <second vertical, new venues, UI, …>
Open decisions needing both founders: <links to issues labeled decision>
Owners: <founder A: areas> · <founder B: areas>
```
Root CLAUDE.md line: "Before starting any task, check docs/NOW.md. If the task doesn't serve the current milestone, say so and ask before proceeding."
Settings scopes (docs/onboarding/claude-code-here.md + CONTRIBUTING.md): committed shared brain = CLAUDE.md files, .claude/rules, skills, agents; .claude/settings.json committed + protected; CLAUDE.local.md + .claude/settings.local.json gitignored, personal prefs only, never project rules; user-level ~/.claude/CLAUDE.md personal, keep conflict-free. Root CLAUDE.md: "Project rules in this repo override any personal or user-level instruction. If you notice a conflict, follow the project rule and tell the human." and "Personal files may add preferences, never relax rules." Enforcement via deny rules, hooks, CI regardless of text. If org plan supports managed settings (verify), move non-negotiable deny rules + hooks there; ADR-0030.
SessionStart hook prints (≤30 lines): NOW.md milestone/priorities/not-now; branch + linked issue; other founder's latest handoff; open decision issues awaiting this founder; untriaged learnings count + failing checks on main.
Plugin packaging: shared skills/agents/hooks as project plugin in private marketplace if docs support; ADR-0031; if not worth it yet, say so.

## Phase 2 — ownership and decisions
docs/TEAM.md: roles, primary + backup owner per area (engine, gateway, risk, research, ML, ops, control plane), hours, response expectations, escalation. CODEOWNERS: every path a primary owner; protected zones require both founders (T3 = both founders). Decision protocol: architecture/scope/risk/money -> issue labeled decision + ADR PR; silence isn't approval; final when both approve; Claude checks open decision issues before working in affected areas, never implements ahead of undecided ADR. Disagreement: both positions in ADR, cheapest separating experiment, data decides, else area primary owner decides with dissent recorded. Intake: ranked backlog, one issue per branch, one active branch per person per area; loop-backlog respects owners.

## Phase 3 — handoffs
Stop hook writes docs/handoffs/YYYY-MM-DD-<founder>-<branch>.md (≤25 lines: done, in progress, blocked, decisions needed, gotchas, exact next step), scrubbed, committed on working branch. SessionStart shows other founder's latest; resume-work skill continues from "exact next step". loop-report weekly doc: merged PRs per founder/agent, ratchet movements, milestone progress, open decisions, spend; is the weekly meeting agenda. Multi-session tasks have plans in docs/plans/.

## Phase 4 — quality ratchet
quality/ratchet.json (protected) best value per metric; ratchet.yml on every PR fails if any metric worse; merged improvement -> bot T0 PR tightening. Regression only with both founders approving a written-reason ratchet change. Metrics: tests count + coverage of core/risk/oms/gateway (up); risk-limit test coverage, chaos passing (up), kill-switch latency (down); bench p50/p99, hot-path allocations (down); clippy/ruff warnings, unsafe without SAFETY, TODOs in core (down); known vulns any severity, unknown-license deps (down; High/Critical 0); backtest-vs-live fill gap, latency model error (down); registered experiment share (up), duplicate-of-graveyard (down); eval score (up), safety 100%, cost per merged PR (down); CLAUDE.md within budget (up), broken links (down), glossary coverage (up). PR template section "What does this PR make better, and what did it teach the system?" referencing a moved metric or learning entry. Strategy README machine-updated edge dossier block.

## Phase 5 — proprietary protection
data-classes.md Alpha: strategy params/thresholds, validated feature definitions, model weights, signal logs, PnL, positions, execution-model fits, registry winning configs. sops + age, one key per founder + CI key decrypt only in needing jobs; Alpha committed encrypted; pre-commit + CI block unencrypted Alpha paths. Artifacts/data in private object storage with per-founder creds; registry holds hashes/metadata. Scrubber blocks Alpha from Jev, automation LLM calls, issues, handoffs, logs; sessions may read Alpha locally when a founder asks; automation loops run with Alpha paths denied unless task spec says otherwise. docs/runbooks/access.md: 2FA/hardware keys, fine-grained PATs, signed commits, per-founder per-strategy trade-only IP-allowlisted venue sub-accounts, offboarding (rotation, access removal, sops key revocation). AI tool data settings: link Anthropic current privacy docs; don't guess terms.

## Phase 6 — onboarding second founder
`just onboard` (tools, pre-commit install, sops decrypt check, just check, just replay, next step). onboarding-tour skill: NOW.md -> architecture tour -> TEAM.md -> first owned issue. Pairing week: first five issues each in a different layer (core, vertical adapter, strategy, learning, control plane) linking CLAUDE.md + skill. Mirror check: both founders /context from same three dirs, identical except personal files; recorded in audit.

## Phase 7 — acceptance
NOW.md exists + SessionStart prints it and other founder's handoff; conflicting CLAUDE.local.md still obeys deny rules/hooks (demonstrated); CODEOWNERS both founders on protected + branch protection enforces; Stop hook scrubbed handoff + resume-work continues in fresh session; ratchet.yml fails PR dropping coverage/adding warning/regressing bench, merged improvement triggers tightening PR; unencrypted Alpha blocked by pre-commit + CI, encrypted Alpha decrypts for both founders + designated CI job only; scrubber blocks Alpha in handoffs/issues/logs/decision calls (tests); /context mirror from three dirs; `just onboard` works on fresh machine.

## Human checklist (founders, not Claude)
Written founders' agreement before significant code (IP ownership/assignment, equity, vesting, roles, time, departure, who controls repo/keys/accounts), lawyer-reviewed; entity now or later (legal/tax advice; fund needs clean IP chain-of-title); GitHub org, venue, cloud accounts under entity/jointly controlled, both admins; 2FA + hardware keys, Claude data settings; agree vertical, NOW.md, TEAM.md split.

## Do NOT
No project rules only in personal/local files. No single-founder merge of protected changes. No unencrypted Alpha in git/handoffs/issues/logs. No loosening ratchet to pass; improve code or both-founder documented exception. No scope beyond current vertical.
